### 层次关系图

```
+---------------------------------------------------+
| 1. 应用与模型层 (Application & Model Layer)       |  <-- 开发者主要交互层
|   - 业务逻辑代码 (C++/Python)                     |
|   - 高层API调用 (e.g., ONNX Runtime API, TensorRT API) |
|   - 模型文件格式 (e.g., .onnx, .engine, .pb)      |
+---------------------------------------------------+
                         |
                         v (将模型文件和推理请求传递给引擎)
+---------------------------------------------------+
| 2. 推理引擎层 (Inference Engine Layer)            |  <-- 核心优化与调度层
|   - ONNX Runtime                                  |
|   - NVIDIA TensorRT                               |
|   - Intel OpenVINO                                |
|   - TensorFlow Lite, etc.                         |
+---------------------------------------------------+
                         |
                         v (调用底层库执行优化后的计算任务)
+---------------------------------------------------+
| 3. 硬件加速库层 (Hardware Acceleration Library Layer) |  <-- 底层计算原语层
|   - NVIDIA: CUDA, cuDNN, cuBLAS                   |
|   - Intel: oneDNN (MKL-DNN)                       |
|   - Cross-platform: OpenCL                        |
+---------------------------------------------------+
                         |
                         v (通过驱动程序与物理硬件通信)
+---------------------------------------------------+
| 4. 硬件与驱动层 (Hardware & Driver Layer)         |  <-- 物理执行层
|   - 物理设备: GPU, CPU, NPU, etc.                 |
|   - 设备驱动: NVIDIA Driver, etc.                 |
+---------------------------------------------------+
```

### 各层次详解

#### 1. 应用与模型层 (Application & Model Layer)

*   **职责**: 定义业务逻辑，表示计算图。这是应用开发者直接接触的层次。
*   **组成**:
    *   **模型格式 (Model Format)**: 描述神经网络计算图的静态文件。例如 `.onnx` 文件定义了网络结构和权重。`.engine` 文件是 TensorRT 优化后的序列化模型。
    *   **高层API (High-level API)**: 开发者在代码中用于加载模型、准备输入数据、执行推理和获取输出的接口。例如 `onnxruntime::Session` 或 `nvinfer1::IExecutionContext`。
*   **关系**: 开发者通过高层API，将模型文件加载到下一层（推理引擎层）进行处理。

#### 2. 推理引擎层 (Inference Engine Layer)

*   **职责**: 模型解析、计算图优化和执行调度。这是实现高性能推理的核心。
*   **组成**:
    *   **ONNX Runtime**: 一个跨平台的推理引擎。它的核心是“Execution Provider”架构，可以选择不同的后端（如 CPU, CUDA, TensorRT）来执行。它扮演着一个“适配器”和“调度器”的角色。
    *   **NVIDIA TensorRT**: 专为 NVIDIA GPU 设计的高性能推理优化器和运行时。它执行图融合、层消除、精度校准（FP16/INT8）、内核自动调整等深度优化，并生成最优的 `.engine` 文件。
    *   **Intel OpenVINO**: 专为 Intel 硬件（CPU, iGPU, VPU）设计的推理工具套件。
*   **关系**: 接收上层传入的模型，对其进行解析和优化，然后调用下一层（硬件加速库）提供的计算原语来执行优化后的计算图。

#### 3. 硬件加速库层 (Hardware Acceleration Library Layer)

*   **职责**: 提供针对特定硬件优化的、底层的、高性能的计算函数（称为“原语”或“内核”）。
*   **组成**:
    *   **CUDA**: NVIDIA 的并行计算平台和编程模型，是其 GPU 生态的基础。
    *   **cuDNN (CUDA Deep Neural Network library)**: 基于 CUDA 的、专门为深度学习操作（如卷积、池化、激活函数）提供高度优化的原语库。TensorRT 和 ONNX Runtime 的 CUDA Provider 都会大量调用 cuDNN。
    *   **cuBLAS (CUDA Basic Linear Algebra Subroutines)**: 提供高性能线性代数运算（如矩阵乘法）的库。
    *   **oneDNN**: Intel 提供的，类似 cuDNN，但针对 Intel CPU 和 GPU。
*   **关系**: 它被推理引擎层调用。例如，当 TensorRT 决定执行一个卷积操作时，它会调用 cuDNN 中最优化的卷积内核函数。

#### 4. 硬件与驱动层 (Hardware & Driver Layer)

*   **职责**: 物理上执行计算指令。
*   **组成**:
    *   **物理硬件**: GPU, CPU 等实际的计算单元。
    *   **设备驱动**: 操作系统与物理硬件之间的桥梁，允许上层软件（如 CUDA）访问和控制硬件资源。
*   **关系**: 它是整个技术栈的基石，接收来自硬件加速库层通过驱动程序发出的指令并执行。

### 总结

整个流程是一个**逐层抽象和委托**的过程：
*   **应用层**定义“做什么”（推理任务和模型）。
*   **推理引擎层**决定“如何高效地做”（优化和调度）。
*   **硬件加速库层**提供“做这件事的工具”（优化的计算函数）。
*   **硬件层**最终“完成工作”（执行计算）。

当你使用 **ONNX Runtime 的 TensorRT Provider** 时，其工作流是：`应用代码` -> `ONNX Runtime API` -> `ONNX Runtime 核心` -> `TensorRT Execution Provider` -> `TensorRT 库` -> `cuDNN/cuBLAS` -> `CUDA` -> `NVIDIA 驱动` -> `GPU`。

当你使用 **原生 TensorRT** 时，其工作流是：`应用代码` -> `TensorRT API` -> `TensorRT 库` -> `cuDNN/cuBLAS` -> `CUDA` -> `NVIDIA 驱动` -> `GPU`。这减少了一个中间层，提供了更直接的控制。
