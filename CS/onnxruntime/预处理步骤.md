```c++
#include <opencv2/opencv.hpp>
#include <vector>
#include <numeric>

// --- 预处理函数 ---
// 输入: 一批裁剪好的 cv::Mat 图像
// 输出: 一个符合模型要求的、合并后的 blob
// 输出参数: 返回这个 blob 的最终形状
cv::Mat preprocess_rec_images(const std::vector<cv::Mat>& cropped_images, std::vector<int64_t>& out_shape) {
    // --- 1. 确定批处理的统一尺寸 ---
    const int rec_img_h = 48; // 模型要求的固定高度
    int max_w = 0;

    // 临时存储调整尺寸后的图像，避免修改原始图像
    std::vector<cv::Mat> resized_images;
    resized_images.reserve(cropped_images.size());

    for (const auto& img : cropped_images) {
        int h = img.rows;
        int w = img.cols;
        float ratio = (float)w / h;
        
        // 计算缩放到48高度后的新宽度
        int rec_img_w = static_cast<int>(rec_img_h * ratio);
        if (rec_img_w == 0) {
            rec_img_w = 1; // 避免宽度为0
        }
        
        // 更新批处理中的最大宽度
        if (rec_img_w > max_w) {
            max_w = rec_img_w;
        }

        cv::Mat resized;
        cv::resize(img, resized, cv::Size(rec_img_w, rec_img_h));
        resized_images.push_back(resized);
    }

    // --- 2. 创建批处理 blob 并进行归一化 ---
    int batch_size = cropped_images.size();
    // 创建一个大的 Mat 来存放所有图像数据
    // CV_32FC3 表示 32位浮点数，3通道
    cv::Mat batch_blob(batch_size, rec_img_h * max_w * 3, CV_32F);

    // 准备一个 vector 来存储每个处理好的图像 blob
    std::vector<cv::Mat> image_blobs;

    for (const auto& img : resized_images) {
        // --- a. 填充到最大宽度 ---
        cv::Mat padded_img;
        // 右侧填充黑色 (0,0,0)
        cv::copyMakeBorder(img, padded_img, 0, 0, 0, max_w - img.cols, cv::BORDER_CONSTANT, cv::Scalar(0, 0, 0));

        // --- b. 归一化 ---
        // HWC -> CHW, 0-255 -> 0-1, (X - mean) / std
        cv::Mat blob = cv::dnn::blobFromImage(padded_img, 1.0 / 255.0, padded_img.size(), cv::Scalar(0.5, 0.5, 0.5), true, false);
        cv::divide(blob, cv::Scalar(0.5, 0.5, 0.5), blob);
        
        image_blobs.push_back(blob);
    }

    // --- 3. 将所有单个 blob 合并成一个大的批处理 blob ---
    cv::Mat final_batch_blob;
    cv::vconcat(image_blobs, final_batch_blob);

    // --- 4. 设置输出形状 ---
    out_shape = {
        static_cast<int64_t>(batch_size), 
        3,                               // channels
        static_cast<int64_t>(rec_img_h), // height
        static_cast<int64_t>(max_w)      // width
    };

    return final_batch_blob;
}
```

### 1. 为什么需要 `cv::copyMakeBorder` 填充到 `max_w`？

**核心原因：为了形成一个规整的、连续的 N-D 张量（Tensor）。**

深度学习模型，尤其是用 ONNX Runtime 这样的框架执行时，其输入不是一个一个独立的图像，而是一个单一的、巨大的多维数组，也就是**张量**。

对于我们的识别模型，其输入张量的形状是 `[batch_size, channels, height, width]`，即一个 4D 张量。我们来分析一下这个形状的含义：

*   `batch_size`: 你一次想处理多少张图片。
*   `channels`: 颜色通道数，固定为 3。
*   `height`: 图片高度，模型要求固定为 48。
*   `width`: 图片宽度。

现在，想象一下如果你不把宽度统一会发生什么。假设你有两张待识别的图片：
*   图片 A: 识别出的文本是 "Hi"，预处理后尺寸为 `[3, 48, 50]`。
*   图片 B: 识别出的文本是 "Hello World"，预处理后尺寸为 `[3, 48, 200]`。

如果你想把这两张图作为一个批次（`batch_size = 2`）送入模型，你期望的输入张量形状应该是 `[2, 3, 48, width]`。但是，这里的 `width` 应该是什么？是 50 还是 200？

**一个张量中的所有子单元必须具有相同的维度。** 你不能创建一个“锯齿状”或“不规则”的张量，其中第一个元素的宽度是 50，而第二个元素的宽度是 200。这在内存布局上是无法实现的，因为张量在内存中是一块**连续的、平坦的（flat）**数据块。

为了解决这个问题，我们必须采取一个策略来让所有图片的维度都统一。最常见的策略就是**填充（Padding）**：

1.  **找到批次中的最大宽度 `max_w`**。在我们的例子中，`max_w` 是 200。
2.  **将所有宽度小于 `max_w` 的图片进行填充**。图片 A 的宽度是 50，我们需要在它的右边填充 `200 - 50 = 150` 个像素宽度的空白区域。图片 B 的宽度已经是 200，所以它不需要填充。
3.  **执行填充**。`cv::copyMakeBorder` 就是做这个工作的。它会在图像的边缘添加指定大小的边框（我们这里只在右边添加）。

经过这个操作后：
*   图片 A 的尺寸变为 `[3, 48, 200]`。
*   图片 B 的尺寸保持为 `[3, 48, 200]`。

现在，这两张图片具有了完全相同的 `[channels, height, width]` 维度。我们就可以把它们在 `batch_size` 这个维度上“堆叠”起来，形成一个规整的、形状为 `[2, 3, 48, 200]` 的 4D 张量。这个张量在内存中是连续的，可以被 ONNX Runtime 正确地理解和处理。

**总结**：填充是为了满足深度学习框架对输入数据必须是**规整矩形张量**的硬性要求，从而实现高效的批处理。

### 2. Blob 是什么？

**Blob** 是一个在计算机视觉和深度学习领域非常常用的术语，它的全称是 **Binary Large Object**。但在深度学习的语境下，它的含义更具体：

**Blob 是指一个为深度学习模型准备的、N 维的、内存连续的数组，它通常用来表示一批图像数据。**

你可以把 Blob 理解为**“预处理完成后的、准备直接送入模型的最终数据块”**。

让我们回顾一下从 `cv::Mat` 到 Blob 的过程：

1.  **原始 `cv::Mat`**:
    *   数据类型通常是 `CV_8UC3` (8位无符号整数，3通道)。
    *   内存布局是 **HWC** (`Height, Width, Channels`)。像素 `(r, c)` 的 R, G, B 值在内存中是相邻的。
    *   像素值范围是 `0-255`。

2.  **模型需要的 Blob**:
    *   数据类型通常是 `float` (32位浮点数)。
    *   内存布局是 **CHW** (`Channels, Height, Width`)。所有 R 通道的值在一起，然后是所有 G 通道的值，最后是所有 B 通道的值。
    *   像素值经过了**归一化** (Normalization)，例如缩放到 `[-1, 1]` 或 `[0, 1]` 的范围。
    *   如果进行批处理，它还包含了 `batch_size` 这个维度，成为 **NCHW**。

**`cv::dnn::blobFromImage` 这个函数就是专门用来完成从 `cv::Mat` 到 Blob 的转换的。**

当你调用 `cv::dnn::blobFromImage(padded_img, ...)` 时，它为你做了以下所有事情：
*   **创建了一个新的 `cv::Mat` 对象（即 Blob）。**
*   **分配了 `float` 类型的内存。**
*   **改变了内存布局**：从 HWC 重新排列为 CHW。
*   **进行了数值转换和归一化**：将 `0-255` 的 `uchar` 转换为 `float`，然后执行你指定的缩放、减均值、除以标准差等操作。

所以，在我们的代码中：
*   `preprocess_rec_images` 函数的最终返回值 `final_batch_blob` 就是一个完美的 Blob。它是一个 `cv::Mat` 对象，但其内部数据已经完全符合 ONNX 模型的要求：`float` 类型、NCHW 布局、归一化、并且批次内的所有图像尺寸都已通过填充统一。
*   这个 Blob 的数据指针可以直接、安全地传递给 `Ort::Value::CreateTensor`，因为它的内存结构正是 ONNX Runtime 所期望的。
